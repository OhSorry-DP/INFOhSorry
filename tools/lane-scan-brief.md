# 레인 배치 메모리 위치 찾기 — C머신 작업 지시

이 문서는 C머신(게임 PC)에서 Claude(Sonnet)가 사용자와 함께 진행할 메모리 실측 작업 지시다.

## 목표

INFINITAS(`bm2dx.exe`)에서 아래 값이 메모리의 어디에 어떤 형태로 있는지 찾는다.

1. **실제 레인 배치** — 1P 7키·2P 7키. RANDOM·R-RANDOM·MIRROR 등으로 그 판에 실제 적용된 배치(스크래치 제외).
2. **SP 플레이 사이드** — 일반 SP 를 1P 쪽에서 쳤는지 2P 쪽에서 쳤는지 직접 나타내는 값.

INF 플레이 기록기가 **결과 화면 진입 후 약 1.5~2초 시점**에 값을 읽어 CSV 에 남길 예정이다. 따라서 그 시점에 값이 남아 있는지가 핵심이다.

## 하지 말 것

- 게임 메모리 **쓰기 금지**. 읽기만 한다.
- INF 소스(`src/`)·문서(`docs/`) 수정 금지. 이번 작업은 위치를 찾는 실측만 한다.
- `git commit` · `git push` 금지. 사용자가 시킬 때만 한다.
- 브랜치를 통째로 바꾸지 마라. `feat/play-logger` 는 main 보다 옛 버전이다. 필요한 파일만 `git checkout origin/feat/play-logger -- tools/...` 로 꺼낸다.

## 이미 알려진 것

- 기록기 구조와 주소 체계는 `docs/play-logger.md` 를 따른다(§3 offsets, §6 CSV 열, §6.1 옵션 값 표, §11 play_speed).
  - `offsets.txt` 의 키는 `playSettings` · `playData` · `currentsong` · `judgeData` · `datamap` · `songList` · `unlockdata` 다.
  - P2 설정 블록은 `playSettings + 0x48` 이다. 배틀 플래그는 `playSettings + 0x28` 이고, play_speed 는 `playSettings + 0x17A0` 이다.
  - 옵션 int 는 0 OFF · 1 RANDOM · 2 R-RANDOM · 3 S-RANDOM · 4 MIRROR · 5 SYNCHRONIZE RANDOM · 6 SYMMETRY RANDOM 이다. DP 는 `settings_p1_11` 의 워드 0 이 왼쪽, 워드 5 가 오른쪽이다.
- 실제 배치를 읽는 코드는 Reflux·INF 어디에도 없다. 2026-11-02 조사 결과다.
- `src/main/playDetail.ts` 의 레인별 판정 카운터(8레인×6판정)는 배치 정보가 아니다. 거기서 배치를 복원하려 하지 마라.
- 결과 화면에는 배치 숫자가 뜨지 않는다(사용자 확인). 그래서 **배치를 미리 아는 판(정배·미러)으로 후보를 좁힌다.**

## 도구

`tools/scan-lanes.ps1` — 알려진 7자리 순열을 메모리 전체에서 찾는 읽기 전용 스캐너다.

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\scan-lanes.ps1 -P1 1234567 -P2 1234567 -Tag off
```

- 찾는 표현은 다음 조합이다: 순열 정방향·역방향 × 값 기준(0·1·7·8 시작) × 간격(1·2·4바이트).
- 결과는 `tools\scan\<Tag>.tsv` 에 `라벨 · 절대주소 · mod+상대주소 또는 heap` 형식으로 남는다.
- 🔴 정배 `1234567` 을 0기준 1바이트로 보면 `00 01 02 03 04 05 06` 이다. 이건 흔한 바이트열이라 후보가 많이 나온다. 반드시 미러와 교집합을 내서 줄여라.
- 필요하면 스캐너를 고치거나 보조 스크립트를 `tools\scan\` 아래에 만들어도 된다. 예: 교집합 계산, 후보 주소만 다시 읽기, 두 스냅샷 비교. 이 폴더 밖은 만들지 마라.

## 진행 순서

모든 라운드는 **게임을 끄지 않은 한 세션 안에서** 한다. 힙 주소는 재시작하면 바뀐다.
측정은 **결과 화면에 머문 상태**에서 한다. 쉬운 곡 하나로 계속 친다.

| 라운드 | 사용자가 칠 옵션 | 확인할 것 |
|---|---|---|
| 1 | DP OFF/OFF | `1234567` 후보 수집 |
| 2 | DP MIR/MIR | `7654321` 후보 수집 → 1과 같은 주소·같은 표현만 남김 |
| 3 | DP MIR/OFF | 남은 후보를 다시 읽어 어느 주소가 왼쪽이고 어느 주소가 오른쪽인지 가름 |
| 4·5 | DP RAN/RAN 두 판 | 후보 주소에 1~7 이 한 번씩 든 순열이 있고 판마다 바뀌는지 |
| 6 | DP R-RAN/R-RAN | 순열이 회전 형태인지 |
| 7 | DP FLIP + MIR/OFF | FLIP 일 때 화면 왼쪽·오른쪽 기준인지 옵션 왼쪽·오른쪽 기준인지 |
| 8·9 | SP 1P RAN, SP 2P RAN | SP 에서 어느 배열이 바뀌는지, 반대쪽 배열은 어떻게 남는지 |
| 10 | SP 1P OFF ↔ SP 2P OFF | 사이드를 직접 나타내는 값 찾기. 두 판의 차이를 `playSettings`·`playData`·`judgeData`·`currentsong` 주변(±0x2000)에서 먼저 보고, 없으면 범위를 넓혀라 |

추가로 확인할 것:

- **잔존 시간** — 결과 진입 직후, 0.5초, 1.5초, 3초 뒤, 그리고 다음 선곡 화면에서 값이 유지되는지.
- **주소 표현** — heap 이면 `offsets.txt` 의 기존 키(특히 `playSettings`·`playData`·`judgeData`)로부터 고정 오프셋이나 포인터 경로로 닿는지. 게임을 한 번 재시작한 뒤에도 같은 경로로 재현되는지 확인하라.
- **방향** — 저장할 문자열은 「화면 왼쪽부터 물리 건반 1→7 자리에 어떤 원래 레인이 왔는가」다. 메모리가 정방향인지 역방향인지 정배·미러로는 가를 수 없다(둘 다 자기 역순열이다). 랜덤 판에서 사용자와 함께 화면으로 확인할 방법을 찾아라. 예를 들어 플레이 시작 때 레인 번호가 표시되는지 보거나, 알려진 채보의 첫 노트가 어느 건반에 떨어지는지 보면 된다.
- **S-RANDOM** — 한 판을 고정 순열 하나로 표현할 수 있는지. 플레이 중에 값이 계속 바뀌는지 보면 된다.

## 사용자에게

- 매 라운드 전에 칠 옵션을 한 줄로 알려 주고, 결과 화면에 도착하면 말해 달라고 해라.
- 질문은 라운드 진행에 꼭 필요한 것만 한다.

## 결과 보고

`tools\scan\REPORT.md` 에 아래를 쓴다.

1. 게임 빌드 버전(`offsets.txt` 첫 줄), 모듈 베이스
2. 레인 배치: 주소 표현(기존 키 기준 오프셋 또는 포인터 경로), 값 형식(바이트·간격·0/1기준·방향), 1P·2P 위치, 라운드별 근거 값
3. 잔존 시간 결과(결과 진입 후 각 시점, 다음 선곡)
4. FLIP·SP·배틀일 때의 의미
5. SP 사이드 값: 찾았으면 주소·값 의미, 못 찾았으면 본 범위와 0건 근거
6. 재시작 뒤 재현 여부
7. 확신 없는 판단·못 끝낸 것
